# croquis

図は `drawing.svg` というファイルに書く。ブラウザのビューアが自動で更新される。API は `http://127.0.0.1:5199/api`。

API が応答しない（connection refused）ときは、先に `croquis open` を実行してサーバーを起動する。

## 図を描く

1. 作成する。返ってくる `drawingPath` が書き込み先
   ```sh
   curl -s -X POST http://127.0.0.1:5199/api/croquis -d '{"title":"認証フロー"}'
   # → {"id":3,"drawingPath":"/…/.croquis/3/drawing.svg"}
   ```
2. `drawingPath` に SVG を Write する
3. アクティブにする（ブラウザのタブが切り替わる）
   ```sh
   curl -s -X PUT http://127.0.0.1:5199/api/active -d '{"id":3}'
   ```
4. `croquis open 3`（ビューアが開いていなければ開く。開いていれば何もしない）

5. フィードバックが要るときだけ、`croquis wait` を**バックグラウンドで**実行して（Bash の `run_in_background`）、応答を終える。ユーザーが「送る」を押すとコマンドが終了し、フィードバックの JSON が出力されて、自動で呼び戻される

### フィードバックを待つかどうか

既定では待たない。図を見せれば用が済むときは、4 で終える。

- 待つ：ユーザーが確認・レビュー・赤入れをすると言ったとき。図そのものが成果物で、これから詰めていくとき（設計案、レイアウト案など）。直前にフィードバックを受けて直したとき
- 待たない：説明の補足として図を添えただけのとき。ユーザーが「待たなくていい」と言ったとき。迷ったとき

待っていなくても、ユーザーが送ったフィードバックはサーバーに残る。「送った」と言われたら「フィードバックを受け取る」の 1 から読めばよい。

## SVG の書き方

- ルートの `<svg>` に `viewBox` を付ける。背景は白の前提（ダークモードではビューアが明るさを反転して表示するので、白地のつもりで描けばよい）
- **主要な要素（ラベル、箱、矢印など）には必ず `id` を付ける**。フィードバックの `targets` はこの id で返ってくる
- `<script>`、`<foreignObject>`、イベント属性は表示のときに取り除かれるので使わない
- **原色の赤 `#ff0000`・青 `#0000ff`・緑 `#00ff00`・黄 `#ffff00` と、それに近い鮮やかな色は使わない**。ユーザーの赤ペンの色なので、図と印の見分けがつかなくなる。図には彩度を落とした色（例：`#c2410c`、`#1e40af`、`#15803d`、`#a16207`）と、その淡い塗りを使う

## 修正する

- 小さな修正は `drawing.svg` を Edit する
- 全体を描き直すときは Write する

## フィードバックを受け取る

`croquis wait` が終了して呼び戻されたときは、その出力が未読のフィードバックなので、3 から始める。ユーザーに「送った」と言われたときは 1 から始める。

1. 対象を確認する（ユーザーがタブで選んだものが入っている）
   ```sh
   curl -s http://127.0.0.1:5199/api/active
   ```
2. 未読のフィードバックを取る
   ```sh
   curl -s http://127.0.0.1:5199/api/croquis/3/feedback
   ```
   - ユーザーは複数のフィードバックをためて一度に送れる。配列に複数入っていることも、複数のクロッキーにまたがることもある（`croquis wait` の出力には全クロッキーの分が入る）。全部を読んでから直す
   - `croquis`：対象のクロッキーの id
   - `comment`：ユーザーのコメント
   - `marks[]`：印ごとの `type`（`path`・`ellipse`・`rect`・`text`）、`text`（`type` が `text` のときの、ユーザーが図の上に書いた文字）、`color`、`dash`、`bbox`（図の座標系で `[x, y, 幅, 高さ]`）、`targets`（囲まれた要素の id）
   - `snapshotPath`：図と赤ペンを重ねた PNG
3. `snapshotPath` の PNG を Read して、見た目を確かめる
4. `drawing.svg` を修正する
5. 既読にする（フィードバックが届いたクロッキーごとに）
   ```sh
   curl -s -X DELETE http://127.0.0.1:5199/api/croquis/3/feedback
   ```
6. もう一度 `croquis wait` をバックグラウンドで実行して、次のフィードバックを待つ。必ず 5 の既読のあとに行う（未読が残っていると、すぐに終了してしまう）。ユーザーが「これで OK」と締めたときや、緑の印だけで直すところがなかったときは、待たずに終える

## 色と線種の約束

- 赤の実線：直してほしい
- 青の破線：ここを参考に、ここと揃えて
- 緑：OK、このまま残して
- 黄：決まった意味はない。コメントを読む
- 矢印（`dash` が `arrow`）：ここからここへ（動かす、つなぐ）。向きは JSON に入らないので、PNG で確かめる

## ユーザーが足した空のクロッキー

ユーザーはビューアの「+」で空のクロッキーを足して、そこに下絵を描いて送ってくることがある。`drawing.svg` はまだないので、`GET /api/croquis/{n}` の `drawingPath` に Write する。

## そのほかの API

- `GET /api/status`：ビューアの状態 `{open, visible, clients, waiting, processing}`（`waiting` は `croquis wait` が待っている間、`processing` は `croquis wait` がフィードバックを受け取ってから既読にするまで true。ビューアに「待機中」「処理中」と表示されるので、対応が済んだら必ず既読にする）
- `GET /api/croquis`：一覧
- `GET /api/croquis/{n}`：取得
- `PUT /api/croquis/{n}`：`{title, drawing}` で更新
- `DELETE /api/croquis/{n}`：削除
